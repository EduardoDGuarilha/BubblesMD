# Bubbles.MD delivery checklist

Application implementation is pending. Finish the selected product and report concrete limitations honestly.

- [ ] The real writing flow works: select, reflect, suggest/refine, inspect/pop changes, accept/reject, and Undo.
- [ ] Focused checks support correct targeting/history; Markdown editing and reload recovery have been exercised.
- [ ] The actual browser experience follows design.md, including a representative difficult layout.
- [ ] Both model modes work; actual spending is visible and within the supplied cap.
- [ ] Builds and a fresh setup/startup work; local ASP.NET publishing has been checked.
- [ ] README describes actual setup, implemented features, storage limits, known issues, and more-time improvements.
- [ ] Genuine AI sessions are included with disclosed credential redactions; public candidate files/history contain no secrets or unintended private inputs.

Use [acceptance.md](../acceptance.md) as a behavior reference, not a requirement for nineteen separate test reports. Fix critical correctness failures; avoid test quotas and cosmetic coverage work. Preserve real observations and unresolved issues in brief progress notes.

A repository link is required by the assessment. Publish a remote, deploy publicly, or send the submission only with applicable user authorization. This checklist does not authorize those actions.
