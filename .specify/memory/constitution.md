# Bubbles.MD project constitution

Version 1.1. Status: specification prepared; application unstarted.

1. **Writer control.** AI proposes a scoped possibility; explicit acceptance commits prose. Preserve review state with acceptance Undo/Redo.
2. **Owned context.** Keep source, scope, thoughts, candidates, and keep-original decisions in app-owned state. Send relevant bounded context from the active review.
3. **Software proof.** Compute diffs, map targets, check revisions, validate output, and apply edits deterministically. A model assertion is not verification.
4. **Measured spending.** Expose Fast/Smart choice and actual recorded cost. Bound requests, prevent duplicates, and avoid automatic retries/upgrades. Unknown cost is not zero.
5. **Coherent experience.** Maintain one logical document across formatted/editable Markdown views and stable left-oriented writing with right-side bubbles.
6. **Simple ownership.** Prefer familiar C#, maintainable TypeScript, browser recovery, and reproducible setup. Match the assessment's scope.
7. **Honest evidence.** Preserve genuine sessions and observed checks. Distinguish requirements, defaults, research judgments, and unproven integration.
8. **Proportionate delivery.** Implement working increments with early AI integration and risk-based verification. Continue an authorized local build without procedural approval gates. Change material product scope explicitly; do not silently weaken essential behavior.

Explicit user instructions and assessment requirements govern. spec.md defines behavior, design.md presentation, and plan/contracts implementation constraints. tasks.md provides a short sequence; acceptance.md provides behavior references and verification guidance. Resolve a real conflict specifically. Historical proposals do not override current documents.
